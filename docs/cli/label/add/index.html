Documentation / CLI

transcript-lake label add

Append one durable, provenance-bearing label to an existing Lake session.

Invocation#

sh
transcript-lake [--data-dir <path>] label add <session-id> --aspect <name> --value <v> [--note <text>] [--runtime <r>] [--source <name[:detail]>] [--json]

Purpose#

Append one durable, provenance-bearing label to an existing Lake session.

Inputs and options#

  • Required <session-id>, non-empty --aspect <name>, and non-empty --value <v>.
  • Optional --note <text>, --runtime <r>, and --json. Runtime accepts claude, codex, omp, droid, kimi, or hooks.
  • --source defaults to manual and accepts manual, human, model, or brama, optionally followed by :detail.

Output and state effect#

Mutating. Resolves exactly one existing session/runtime, appends one complete record to labels/labels.ndjson, and fsyncs before success. It does not take the event-writer lease. Human output confirms the assignment; JSON emits the record.

Exact refusals#

  • Missing aspect: --aspect must be a non-empty string.
  • Missing value: --value must be a non-empty string.
  • Unknown session: unknown session "<session-id>": not present in the selected Lake (check the id or start the stream first).
  • Ambiguous runtime: session id "<session-id>" is ambiguous across runtimes (<runtimes>); repeat with --runtime.
  • Invalid provenance: --source must match ^(manual|human|model|brama)(:[A-Za-z0-9._/-]+)?$ (manual, human, model, or brama, with an optional :detail suffix).

All long flags are exact and single-use. A value flag never consumes another --flag. Global --data-dir may appear anywhere in the invocation, must appear once, and selects an absolute root.
